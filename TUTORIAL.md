## 1. What This Pipeline Does

The pipeline compares two parallel text corpora — a **canonical** (linguistically complete) register and a **reduced** (compressed or simplified) register — at five linguistic levels:

| Level | What is analysed |
|-------|-----------------|
| Character | Entropy, n-gram patterns, average word length, MATTR |
| Token | TTR, MATTR, MTLD, HD-D, Yule's K, Brunet's W, Honore's H, lexical density |
| Morphological | POS distribution, CoNLL-U feature entropy, feature-value TTR |
| Dependency | Mean Dependency Distance (MDD), deprel entropy, long-dependency proportion |
| Constituency | Tree depth/branching, subordination index, production rule entropy |

**Task 1** extracts pairwise *transformation events* (e.g., article deletion, tense change, relative-clause removal) annotated against a linguistic ontology (schema v5.0) and runs statistical tests.

**Task 2** learns transformation rules from those events and uses them to automatically transform sentences in both directions (canonical→reduced and reduced→canonical), ranking multiple hypotheses by fluency and adequacy.

**Task 3** computes information-theoretic complexity and cross-register similarity at all levels, producing accumulated-level curves and directional asymmetry analyses.

## 3. Data Format Requirements

### 3.1 Plain-Text Corpus Files

- One sentence per line, UTF-8 encoding
- No blank lines between sentences
- Canonical and headline files must have **identical line counts** (parallel alignment)

```
# Example: canonical.txt
The government announced new education reforms yesterday.
Scientists discovered a new species of frog in the Amazon.

# Example: headlines.txt
Govt announces education reforms
New frog species found in Amazon
```

### 3.2 Dependency Parses — CoNLL-U Format

Generated by Stanza. Each sentence block ends with a blank line. Fields (tab-separated):

```
id  form  lemma  upos  xpos  feats  head  deprel  deps  misc
```

**Important**: the current `conllu` library (>=6.0) uses `.get('upos')` to access the UPOS field — not `upostag`. Older code that uses `upostag` will raise a KeyError.

```
# CoNLL-U example
1  The      the      DET   DT  Definite=Def|PronType=Art  2  det    _  _
2  government  government  NOUN  NN  Number=Sing              4  nsubj  _  _
3  announced   announce   VERB  VBD  Mood=Ind|Number=Sing|...  0  root   _  _
```

### 3.3 Constituency Parses — NLTK Tree Format

One bracketed tree per line (sentence marker line followed by blank line in the constituency file format used internally, but the raw file should have one tree per line):

```
(ROOT (S (NP (DT The) (NN government)) (VP (VBD announced) (NP (JJ new) (NNS reforms)))))
(ROOT (S (NP (NNP Govt)) (VP (VBZ announces) (NP (NNS reforms)))))
```

### 3.4 Parallel Alignment

The pipeline aligns sentence pairs by line number. Line 1 of the canonical file corresponds to line 1 of the headlines file, line 2 to line 2, etc. If your data has multiple sentences per document, you need to split and align them first.

## 4. Generating Parses for Your Own Data

### 4.1 Dependency Parsing with Stanza

```python
import stanza

# Download English models (first time only)
stanza.download('en')

nlp = stanza.Pipeline('en', processors='tokenize,mwt,pos,lemma,depparse',
                       tokenize_no_ssplit=True)   # treat each line as one sentence

with open('my_canonical.txt') as fin, open('my_canonical_deps.conllu', 'w') as fout:
    for line in fin:
        line = line.strip()
        if not line:
            continue
        doc = nlp(line)
        for sent in doc.sentences:
            # Print CoNLL-U
            for word in sent.words:
                feats = word.feats if word.feats else '_'
                misc  = '_'
                print(f"{word.id}\t{word.text}\t{word.lemma}\t{word.upos}\t{word.xpos}"
                      f"\t{feats}\t{word.head}\t{word.deprel}\t_\t{misc}", file=fout)
            print(file=fout)  # blank line between sentences
```

Run the same script for both canonical and headline files.

### 4.2 Constituency Parsing with Benepar

```python
import benepar, spacy

# Setup (first time)
benepar.download('benepar_en3')
nlp = spacy.load('en_core_web_md')
nlp.add_pipe('benepar', config={'model': 'benepar_en3'})

with open('my_canonical.txt') as fin, open('my_canonical_const.txt', 'w') as fout:
    for line in fin:
        line = line.strip()
        if not line:
            continue
        doc = nlp(line)
        # Each spacy sentence has a _.parse_string attribute
        for sent in doc.sents:
            print(sent._.parse_string, file=fout)
```

Alternatively, the Stanza pipeline can also produce constituency parses when `processors='tokenize,...,constituency'` is set — check the Stanza docs for the appropriate model.

### 4.3 Verifying Parse Alignment

```python
# Quick sanity check: line counts must match
with open('my_canonical.txt') as f:
    n_canonical = sum(1 for l in f if l.strip())

with open('my_canonical_const.txt') as f:
    n_const = sum(1 for l in f if l.strip())

assert n_canonical == n_const, f"Mismatch: {n_canonical} vs {n_const}"
print("OK")
```

For CoNLL-U, count sentence blocks (blank-line delimited):

```python
import conllu
with open('my_canonical_deps.conllu') as f:
    sentences = list(conllu.parse_incr(f))
print(f"CoNLL-U sentence count: {len(sentences)}")
```

## 6. Adapting for Different Registers

### 6.1 What "Canonical" and "Reduced" Mean Abstractly

The pipeline treats register A as "canonical" (source of truth) and register B as "reduced" (derived or compressed). This is a modelling convenience: all events are expressed as A→B transformations. You can assign any two registers to these roles.

### 6.2 Register-Agnostic Features in Schema v5.0

Most features in `data/diff-ontology-ver-5.0.json` apply to any register pair:
- `FW-DEL` — function word deletion (articles, prepositions, auxiliaries, conjunctions)
- `C-DEL` — content word deletion
- `FEAT-CHG` — morphological feature change (tense, number, case, etc.)
- `DEP-REL-CHG` — dependency relation change
- `LENGTH-CHG` — sentence length change
- `TED-*` — tree edit distance measures
- `FORM-CHG` — surface form change (spelling, abbreviation, capitalisation)

### 6.3 Headline-Specific Features to Consider Disabling

If your register pair is not headline vs. full sentence, consider disabling or reweighting these features:
- `PUNCT-ADD` / `PUNCT-DEL` — punctuation changes (less relevant for same-domain registers)
- `HEADLINE-TYPO` — headline-specific typographic conventions (capitalisation, numerals, abbreviations)

Disable by setting the feature's `active` field to `false` in the ontology JSON, or filter events by feature ID after extraction.

### 6.4 Worked Examples

#### Formal vs. Informal (Social Media vs. News)

- Register A (canonical): news articles
- Register B (reduced): tweets / social media posts
- Expect: heavy FW-DEL, FEAT-CHG (capitalisation, tense), abbreviation FORM-CHG
- Disable: HEADLINE-TYPO (replace with SOCIAL-TYPO if needed)

#### Original vs. Simplified Text

- Register A (canonical): original text
- Register B (reduced): simplified version (e.g., Simple Wikipedia)
- Expect: C-DEL (complex words), shorter sentences (LENGTH-CHG), clause removal (DEP-REL-CHG)
- TED metrics will show high structural distance between parse trees

#### Spoken Transcripts vs. Written Prose

- Register A (canonical): edited written prose
- Register B (reduced): spoken transcript
- Expect: disfluency insertions in B (FW-ADD), shorter dependency distances in B, lower constituency tree depth

#### L1 vs. L2 Learner Text

- Register A (canonical): native speaker text
- Register B (reduced): learner text (missing articles, tense errors)
- Expect: FEAT-CHG (tense errors), FW-DEL (article omissions), lower morphological richness in B

**Event distribution heatmap**: rows = schema features (FW-DEL, FEAT-CHG, etc.), columns = newspapers. Darker cells = more frequent transformations. Useful for identifying which newspapers differ most in register.

**Chi-square results**: tests whether each feature's distribution differs significantly between canonical and headline registers. Low p-values = feature is systematically different. Odds ratios > 1 mean the feature is more common in the reduced register.

## 8. Running Task 2 — Transformation Study

### 8.1 Prerequisite

Task 1 must have been run for each newspaper — the `events_global.csv` files are required inputs for rule extraction.

### 8.2 Rule Extraction

```bash
python run_task2_transformation_study.py
# or for specific newspapers:
python run_task2_transformation_study.py --newspapers "Times-of-India" "The-Hindu"
```

### 8.3 Bidirectional Transformation

```bash
python run_bidirectional_transformation.py
```

This uses an 80/20 train/test split. Training sentences provide the rule inventory; test sentences are transformed using the learned rules. Eight hypothesis strategies are generated per sentence (H0=high-confidence rules, H1=all rules + constituency, H2=feature changes only, H3=deletions + form changes, H5/H6=random subsets, H7=identity). The best hypothesis is selected by a CandidateRanker combining fluency (trigram LM, α=0.6) and adequacy (token overlap, α=0.4).

### 8.4 Evaluation Metrics

| Metric | What it measures |
|--------|-----------------|
| **Jaccard** | Token-set overlap between generated and reference |
| **BLEU** | N-gram precision (1–4 grams) with brevity penalty |
| **WER** | Word Error Rate — edit operations normalised by reference length |
| **FEATS accuracy** | Proportion of morphological features matching reference |
| **DEPREL accuracy** | Proportion of dependency relations matching reference |

### 8.5 Key Outputs

```
output/transformation-study/bidirectional-transformation/
├── generated/
│   ├── {Newspaper}_c2r_results_test.csv   # Canonical→Reduced per sentence
│   └── {Newspaper}_r2c_results_test.csv   # Reduced→Canonical per sentence

│   └── {Newspaper}_evaluation_summary.csv
```

## 9. Running Task 3 — Complexity & Similarity Study

### 9.1 The Comprehensive Runner

```bash
python comprehensive_task3_runner.py
```

This orchestrates all sub-analyses:
1. Extended multi-level complexity (character through constituency + lexical diversity)
2. Extended multi-level similarity (character similarity, Wasserstein, explicit C2H/H2C, symmetrized)
3. Transformation-based complexity/similarity (rule entropy, coverage, directional asymmetry)
4. Accumulated-level analysis (L1–L6 curves with information gain)
5. Cross-newspaper aggregation and 8 publication figures

### 9.2 What Each Level Measures

| Level | Key metrics |
|-------|-------------|
| L1 Character | char entropy, char n-gram entropy, MATTR on characters, avg word length |
| L2 Token | TTR, MATTR (window=50), MTLD, HD-D, Yule's K, Brunet's W, Honore's H, lexical density |
| L3 Morphological | POS entropy, feature-type entropy, morphological richness index |
| L4 Dependency | MDD, MDD normalized, deprel entropy, dep distance entropy, proportion long deps (>5) |
| L5 Constituency | avg tree depth, branching factor, subordination index (SBAR/S), clause density, production rule entropy, right-branching ratio |
| L6 TED | Tree Edit Distance (simple, Zhang-Shasha, Klein, RTED), normalized TED |

### 9.3 Reading accumulated_levels_comparison.csv

Each row is one (newspaper, level) combination. Key columns:

- `accumulated_entropy_canonical` / `accumulated_entropy_headline`: running average entropy up to that level
- `information_gain`: how much adding this level increases the accumulated signal
- `accumulated_jaccard` / `accumulated_js_similarity`: accumulated cross-register similarity

A steeply rising information_gain curve at a particular level means that level captures register differences not captured by earlier levels.

### 9.4 Interpreting Directional Asymmetry

For asymmetric metrics (KL divergence, cross-entropy):
- `metric_C2H`: canonical distribution used as reference, headline as approximation
- `metric_H2C`: headline distribution as reference, canonical as approximation
- `metric_symmetrized`: arithmetic mean of both directions

High `kl_C2H` with low `kl_H2C` means the headline distribution is a good approximation of the canonical, but not vice versa — i.e., headlines cover a narrower portion of the canonical vocabulary/structure.

### 9.5 Key Output

```
output/complexity-similarity-study/global/comprehensive_metrics_all_levels.csv
```

This is the master table consolidating all metrics across all newspapers and levels. Load it with pandas for downstream analysis:

```python
import pandas as pd
df = pd.read_csv('output/complexity-similarity-study/global/comprehensive_metrics_all_levels.csv')
df.groupby(['newspaper', 'level'])['information_gain'].mean()
```

## 11. Common Issues and Troubleshooting

### "upostag not found" / KeyError on CoNLL-U token dict

The `conllu` library changed its API at version 5.0. Use `token.get('upos')` instead of `token['upostag']`. This is already fixed in the current codebase (see `MEMORY.md`), but older scripts in `older-code/` may still use the old key.

### "Tree count mismatch" warning

The constituency parser may produce multi-sentence trees for inputs that nominally have one sentence. The pipeline warns when constituency parse counts differ from sentence counts and continues by truncating to the shorter count. This is expected behaviour for complex sentences.

### Memory issues on large corpora

If you have corpora with tens of thousands of sentences, the constituency TED computation can be memory-intensive. Mitigate:

```bash
# Limit parallelism
OMP_NUM_THREADS=1 python comprehensive_task3_runner.py

# Use simple TED only (in ted_config.py)
# Change TEDConfig.default() to TEDConfig.simple_only()
```

### WSL2 path issues

`config.py` auto-detects WSL and uses native Linux paths (`/mnt/...`). If you see UNC path errors (`//wsl$/...`), check that `config.py` is being imported correctly and that `BASE_DIR` resolves to the right location:

```python
from config import BASE_DIR
print(BASE_DIR)   # Should be a /mnt/... or /data/... path, not \\wsl$\...
```

### NLTK data not found

```bash
python -m nltk.downloader punkt punkt_tab averaged_perceptron_tagger averaged_perceptron_tagger_eng
```

Or from Python:

```python
import nltk
for pkg in ['punkt', 'punkt_tab', 'averaged_perceptron_tagger', 'averaged_perceptron_tagger_eng']:
    nltk.download(pkg)
```

### Constituency file line count differs from text file

The `MultiLevelComplexityAnalyzer` and `MultiLevelSimilarityAnalyzer` read constituency trees one per line. If Stanza produced multi-tree outputs (one sentence split into two trees), you'll see a mismatch. Fix by filtering the constituency file to keep only the first tree for each input sentence:

```bash
# Quick check
wc -l data/input/input-single-line-break/Times-of-India-corrected-canonical.txt
wc -l data/input/constituency-parsed/Times-of-India-canonical-stanza-parsed-constituency.txt
```

### Import errors for project modules

The project uses an `import sys; sys.path.append(...)` pattern. When running scripts from the project root, all paths resolve correctly. If you run scripts from a different working directory, prepend the project root to `PYTHONPATH`:

```bash
export PYTHONPATH=/path/to/ReducedToCanonicalConvDiff:$PYTHONPATH
```

### Schema feature not found

If `SchemaBasedComparator` throws a feature-not-found error, verify that you are using schema v5.0:

```python
from register_comparison.meta_data.schema import Schema
s = Schema()
print(s.version)  # Should be '5.0'
```

If it shows an older version, check that `paths_config.py` points to `data/diff-ontology-ver-5.0.json`.
